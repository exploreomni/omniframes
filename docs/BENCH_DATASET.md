# The Omniframes bench dataset

A single, deterministic, synthetic ecommerce dataset used by **every** test lane — the
FakeOmniAPI's backing tables, the differential lane's ground truth, the demo notebook — and
designed to be loaded into a real warehouse behind a real Omni model for live integration tests.
One dataset everywhere means a bug reproduced offline is the same bug seen live.

## Layout

```
tools/bench/generate.py       # deterministic generator (seeded; no wall-clock dependence)
tests/data/bench/             # checked-in artifacts at scale=1
  users.parquet / users.csv
  products.parquet / products.csv
  order_items.parquet / order_items.csv
  known_answers.json          # precomputed aggregate results (DuckDB) for known-answer tests
docs/BENCH_DATASET.md         # this spec
docs/bench_omni_model.md      # Omni model/topic YAML sketch for the live org (M0e output)
```

Regenerate with `uv run python tools/bench/generate.py` (add `--scale N` for larger live loads —
scales the fact table only; dimensions stay fixed so join selectivity is stable).

## Schema (scale=1)

Anchor date: **2026-06-30** (fixed; the generator never reads the clock). RNG: numpy
`default_rng(42)`. Any change to schema or distributions bumps `BENCH_VERSION` and regenerates
`known_answers.json` in the same commit.

### `users` — 500 rows
| column | type | edge cases baked in |
|---|---|---|
| id | int64 PK (1..500) | — |
| name | string | unicode names (CJK, emoji, accents) |
| email | string | — |
| state | string, **~6% NULL** | NULL group keys for group-by tests |
| country | string (US-heavy, 8 countries) | — |
| created_at | timestamp[us, tz=UTC] | spans 5 years |
| age | int64, **~8% NULL** | nullable numeric aggregation |
| is_business | bool, **~5% NULL** | three-valued logic |
| signup_source | string, low cardinality | includes `""` (empty ≠ NULL) |
| lifetime_value | decimal128(12,2) | decimal Arrow type on the wire |

### `products` — 200 rows
| column | type | edge cases |
|---|---|---|
| id | int64 PK | — |
| name | string | unicode incl. emoji |
| category | string, **~4% NULL** | NULL group key |
| brand | string | duplicated across categories |
| cost | decimal128(10,2) | — |
| price | decimal128(10,2) | some price < cost (negative margin) |
| introduced_on | date32 | date (not timestamp) type |

### `order_items` — 10 000 rows (fact)
| column | type | edge cases |
|---|---|---|
| id | int64 PK | — |
| order_id | int64 | ~2.6 items/order; duplicates by design |
| user_id | int64 FK | **~1% orphans** (no matching user) — join-edge testing |
| product_id | int64 FK | — |
| created_at | timestamp[us, tz=UTC] | 2 years ending at anchor; clustered seasonally |
| status | string enum | complete / shipped / processing / cancelled / returned |
| quantity | int64 (1..8) | — |
| sale_price | decimal128(12,2) | per-unit × quantity already applied |
| discount | decimal128(12,2), **~70% NULL** | sparse nullable decimal |
| returned | bool, **~3% NULL** | — |
| notes | large_string, **~90% NULL** | occasional multi-KB text; newlines + quotes inside |

## The governed model over it

The FakeOmniAPI serves (and the live org should define) model **`bench_ecommerce`**, topic
**`order_items`** (base view `order_items`, joins → `users` on `user_id`, → `products` on
`product_id`), with measures:

| field | definition |
|---|---|
| `order_items.total_sale_price` | `SUM(sale_price)` |
| `order_items.count` | `COUNT(*)` |
| `order_items.total_quantity` | `SUM(quantity)` |
| `order_items.average_sale_price` | `AVG(sale_price)` |
| `users.count` | `COUNT(DISTINCT users.id)` |
| `products.count` | `COUNT(DISTINCT products.id)` |

All base columns are dimensions (timestamps get the standard grain set). This mirrors Omni's own
demo-model conventions so live setup tomorrow is a straight load-and-model exercise.

## `known_answers.json`

Generated by DuckDB at generation time; keyed by a stable query id. Includes at minimum:
grand totals (revenue, rows, distinct buyers), revenue by `users.state` (NULL state included),
monthly revenue for the trailing 12 months from the anchor, revenue by category × month,
distinct buyers by month, and the mixed-aggregation case (revenue + distinct buyers by state).
Differential and known-answer tests assert against these — never against a re-computation inside
the test itself.

## Invariants tests may rely on

- Row counts: exactly 500 / 200 / 10 000 at scale=1.
- NULL presence: every percentage above is guaranteed non-zero at scale=1.
- Orphan `user_id`s exist; every `product_id` resolves.
- `sale_price > 0`; `discount`, where present, `>= 0` and `< sale_price`.
- All timestamps UTC; `created_at` max == anchor date for at least one row.
- Deterministic: regenerating at the same `BENCH_VERSION` is byte-identical (Arrow writer
  options pinned).
